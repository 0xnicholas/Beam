数据从哪来，红线在哪

模型的口味全部来自数据。这个项目的数据策略只有两条不可谈判的红线和一套可迭代的配比主张——其余的都是假设，红线不是。

约 15 分钟 数字来自冻结语料与 pilot 蒸馏实跑记录 配套：术语表 · 课程目录

01三类负载，三种来源

训练集不是「找一批文本」，而是照着生产里会被压缩的东西配出来的。生产的压缩面是显式启用压缩档的工作区，被压的文本就三类：

负载类型来源冻结条数为什么这么取
RAG 长文LongBench 公开子集（hotpotqa + gov_report，取 train 半侧）300公开打底：基座模型已在这种文风上训过，作用是锚住通用抽取能力
system prompt合成：10 个手写场景族 × 种子变体350没有公开数据集；生产风格只能造
多轮对话历史合成：同样 10 族 × 种子变体350受隐私边界约束不可采集，只能造

配比锚点是 30% / 35% / 35%，形状是「公开打底 + 两类加重」。加重后两类的理由很直白：缺口在那里——公开数据集对生产风格 system prompt 与多轮历史没有覆盖，微调的收益只可能落在它们身上。合成的占比另外有一个上限（约 2/3），防止把模型过拟到模板文风——占比过高时，考卷上的合成条目会虚高而真实负载不涨。

合成层不是「让模型随便写」：10 个场景族是手写的，种子只负责填槽位（每族几十到几百种组合）。选取器的规则是确定性的——同输入同输出——且逐族录取计划全部写进 manifest 并 sha256 锚定。重建入口：scripts/build_synthetic_training.py。

02蒸馏五步：把「教师怎么删词」变成标签

有了 1000 条语料还只是原料。真正教会模型的是一个教师模型在这些文本上删了什么，而这个行为要被还原成逐词标签：

  1. 切块。每条语料按 ≤512 token 切开，优先在句边界断。1000 条 → 7322 个块，其中 65 个是纯标点/空白的残片（无词可标，跳过不计费）。
  2. 教师压缩。固定 prompt 要求教师只删不改：「你可以只删除不重要的词 / 不要改变词序 / 不要改动原词 / 不要用缩写或 emoji / 不要新增词或符号」。教师是 deepseek/deepseek-v4-pro，模板版本 llmlingua2-paper-v1（sha256 84581c12…）。
  3. 滑窗模糊匹配。把教师输出里的词逐个对回原文位置（窗口 150 个词），得到逐词的 keep / drop 标签。它是启发式，必然有对不齐的地方。
  4. 质控。先丢掉变差率最高的 5%（教师输出了原文里找不到的词 → 疑似幻觉），再丢掉幸存者里对齐间隙最差的 10%（标签对不齐）。
  5. 微调。用剩下的标签训练一个双向编码器——就是推理时跑的那个 checkpoint。

下面这台机器用的是真实样本：左边是教师写的压缩结果，下面是匹配器把保留标签打回原文的样子，最后是这一条在质控里的判定。

样本来自冻结的 pilot 蒸馏产物（training/distill/pilot-v1/，115 条语料 / 299 个块 / 保留 255 个）。「边界样本」的标签 gap = 0.0049 正好压在切线上——它是这一批里被保留的最后一名，再差一点就被丢掉。

两个从真实数字里看出来的东西：

  • 教师比想象中保守。它的平均保留率是 0.7319（中位数 0.7046）——删掉约四分之一，而不是大刀阔斧。压缩率的天花板从一开始就被教师的行为定住了。
  • 哪一类被质控丢得最多？system prompt：60 个块里丢了 20 个（33%），而 RAG 只丢 17/149、对话丢 7/90。规则化的长清单文本更容易让「只删不改」的要求翻车——这类样本的标签质量天然更脆。

03红线一：MeetingBank

MeetingBank（会议纪要语料）看起来是一份完美的公开数据集——长文本、干净、有标注。它被硬拒，连评测集都不能进。原因一句话：

硬约束 1

MeetingBank 是基座 checkpoint 的训练集。用它训练 = 教学生在考卷上背答案；用它评测 = 用学生背过的题考他。两条路都会让「优于公开 checkpoint」这个结论失去意义。

这条约束不是写在文档里的君子协定，而是代码里的硬检查——语料校验器对来源做字符串匹配，命中即判违约：

# src/leia/corpus.py:404 —— 训练语料校验器
if "meetingbank" in f"{source.get('dataset','')}/{source.get('subset','')}".lower():
    fail("MeetingBank is excluded by hard constraint (base checkpoint training set)")

冻结 manifest 里同时记录了三类排除（exclusions 字段）：MeetingBank、客户 prompt、以及任何 train_use=false 的子集。团队要记住的是一般化的那条：

新增数据集前的三问

  1. 它是不是基底 checkpoint（LLMLingua-2）用过的东西？——是，就是污染，出局。
  2. 它里面有没有客户内容？——有，出局，无例外。
  3. 逐文档的许可能不能核验到「允许训练」？——核验不了，只进考卷，不进训练。

04红线二：客户 prompt

生产的压缩发生在客户请求上，那些文本是最真实、最对口味的训练数据——而且永远不能碰：不能训练，也不能评测。这是隐私边界与 ZDR（零数据保留）workspace 承诺的直接推论，没有讨论余地。

这条红线的代价很具体：生产风格 system prompt 与多轮对话这两类没有公开数据集可用，只能靠合成（第 1 节的 700 条）。换句话说，合成层不是偷懒，是被隐私边界逼出来的唯一选项——这也是它为什么值得被认真设计（场景族、种子限制、防模板过拟）。

同理可推：任何「把线上流量捞一点出来做分析」的提议，在数据进入训练或评测之前就被这堂课拦下。要分析就分析聚合指标，不碰 prompt 内容。

05切分纪律：教材与考卷不能同源

「训练集和评测集要分开」人人都知道，难的是在合成数据上怎么做到——合成数据来自同一套生成器，天然同源。项目的做法是两道锁：

  1. 种子池互斥。考卷用 101–110，训练用 901–990（预留 headroom，不是配额）。两侧校验器互相断言：考卷侧生成器对训练种子直接报错，训练侧对考卷种子报错。
  2. 内容层再断言一次零重叠。因为不同种子也可能渲染出逐字节相同的文本（槽位池小的族里是常态）——选取器在内容层去重，并断言与考卷指纹集合零交集。

公开语料那边用另一种可复现的切法：把条目按 sha1(内容) 升序排列，前一半给考卷、后一半给训练。切分由内容决定，不靠随机数——任何人重跑都能得到同一刀，也永远不会有条目跨过边界。

为什么合成语料的训练段与考卷段必须用互斥的种子池？

07花钱的纪律：先归档决策，再花钱

教师调用是要付费的，全量蒸馏的预算是 ≤7257 次网关调用（输入约 4.2M token）。项目在这件事上的做法有两条可复制的纪律：

  • 先决策归档，后花钱。定容决策文件先写清楚总量、配比、teacher、预算与超支处置，再开跑；数字对不上就中止回炉，不静默追加。
  • 崩溃零成本重放。每次调用按内容地址记账（chunk 字节 + teacher + prompt + 分块参数）。kill 掉进程再重启，只会补跑没入账的块——pilot 的 299 次调用在全量跑里原样重放、零计费。

还有一个「不省钱」的决定同样值得看：全量语料里 RAG 类占了 84% 的块（长文天然块多，质控前口径），而 system prompt 只占 5%。团队里常见的直觉是下采样到 30/35/35——项目的决定是不下采样：那等于丢掉已付费、已质控合格的监督信号，还会引入位置偏差；条目层的配比（30/35/35）已经在控制分布覆盖，行层的倾斜留给阶段 3 的验收数据回答。

08收尾：三句话

记住这三句就够用

  1. 数据照着生产负载配，不照着考卷配。三类负载 30/35/35：公开打底 + 两类合成加重。
  2. 两条红线不可谈判。MeetingBank 是基底训练集（污染），客户 prompt 是隐私边界（无例外）——两者都硬编码在校验器里。
  3. 教材与考卷必须不同源。公开集按内容哈希对半切，合成集用互斥种子池 + 内容层零重叠断言。

不看上文，写一遍

有同事问：「既然线上 prompts 最真实，为什么不捞一点来训练？」用三句话回答，并说出你会怎么验证这个回答真的被执行了。

1. 客户 prompt 是隐私边界，无例外——训练与评测都不允许，这是对 ZDR workspace 的承诺，不是可以权衡的成本项；
2. 真实不等于可用——生产风格分布可以用合成数据逼近（场景族 × 种子），代价是多样性受模板约束，项目用「合成封顶 2/3 + 公开 30% 打底」对冲；
3. 验证方式：看校验器与冻结 manifest——exclusions.customer_prompts 字段、语料校验器拒绝非许可来源、以及单测里对这些拒绝路径的断言。口头的纪律要靠代码里的拒绝来证明。
