读表五问

拿到任何一张 Beam 的数字表，先问这五句。五句都答得上来，数字才能被引用。

配套课文：第 02 课 · 怎么读我们的数字

1五问

  1. 口径。计费（tiktoken cl100k_base）还是模型原生（WordPiece / SentencePiece）？字符串级还是 token 级？——同一个压缩率有两个值，方向还可能随底座翻转。
  2. 钉子。作答模型、judge 模型、rubric 版本与哈希、harness commit、考卷哈希、bootstrap 种子——和你要比的那份报告是否一致？换一根钉子就是换了一把尺。
  3. 对照与档位。跟谁比？是不是同一档 aggressiveness？压缩率是结果不是设定值，跨档位的数字不可比。
  4. 指标层级。代理指标（压缩率 / fact recall / token F0.5）还是主指标（任务级质量 delta）？优劣声称只认主指标。
  5. 区间与样本量。均值必须带 95% 区间；样本量决定这个区间有没有分辨力（149 条 vs 45 条 vs 15 条，差别巨大）。

2四个指标的定义

指标口径回答的问题已知陷阱
压缩率 1 − 保留率；计费与原生双计 账单会省多少 / 模型删了多少 两个口径从不相等；方向随 tokenizer 翻转（mBERT 原生 > 计费，XLM-R 原生 < 计费）
fact recall 原文事实在压缩文本中逐字存活的比例（字符串包含） 数字、编号、百分比还在不在 受解码空格影响：#A-1029 → # A - 1029 会被记为丢失（第 01 课诊断）
token F0.5 token 级对齐，β²=0.25（精确率权重 ×2）；harness 用恒等对齐，运行时用 embedding 余弦 压缩结果还像不像原文 保留越多它越高，与任务质量无关（XLM-R 0.889 也没赢）
任务级质量 delta 同一 prompt 原文与压缩后各答一次，judge 按 key_points 打分之差 下游答案变好还是变差 样本量小会给出假区间；judge 与 rubric 必须钉死

4常见误读（都是真实发生过的）

  • 「压缩率 47.5%，比公开模型高」——如果不同档位，这两句话没有可比性；档位是阈值，不是比例。
  • 「均值 +0.0095，略有提升」——区间跨零时说「提升」是过度解读，正确说法是「无可分辨差别」。
  • 「fact recall 0.7699，说明模型会丢事实」——它说明测量方式会记丢；事实每个字符都在（诊断见第 01 课，定案待复核）。
  • 「token F0.5 高了，质量更好」——这是代理指标，两个底座上它差异很大而任务质量差异不大。
  • 「把这批数字和旧 benchmark 的 60 条比一比」——考卷、钉子、口径全变了，只有一个共同点：都不该混用。
