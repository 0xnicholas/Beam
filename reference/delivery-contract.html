交付与接入速查

替换的边界、契约四条、产物包五件、切换与回滚——评审或接入前扫一眼的那一页。

1替换边界：变与不变

变不变
compress 阶段的 checkpoint 权重 rewrite 阶段（网关 LLM 回调）与它的两道 guardrail
缓存键里的压缩机标签（当前值 → 新值） /refine 协议、请求/响应字段语义
按压缩机标签分组的 token 节省指标 x-tc-refine* 头 / refine_mode / refine_tier / aggressiveness 语义
—— fail-open 与 light mode（宿主 ADR-0011）、x-tc-refine: skipped 标记
—— 三项 guardrail 与 _FACT_PATTERN 强制保留
—— 缓存 LRU/TTL、超时、隐私边界（sidecar 只见 prompt 文本）

影响面：RefineTier 默认 Off（crates/gateway/src/settings.rs:77-80），压缩只在显式启用 rewrite_compress 档的工作区生效（pipeline/transform.rs:241）。收益与出事的爆炸半径是同一批流量。

2drop-in 契约四条

#条件宿主依赖违反的后果
① architectures 含 BertForTokenClassification；num_labels == 2；id2label = {0: drop, 1: keep} 保留概率取 softmax(logits)[..., 1]——位置语义 写反 = 静默反向（能加载、不报错、压缩照跑）
② tokenizer 为 fast，return_offsets_mapping 可用 force-keep 用 offsets 把事实区间映射到 token 事实保护失效；慢 tokenizer 直接调不动
③ 模型类暴露 .bert 属性 refiner.py:338 直调 self.compressor.model.bert(**inputs) 抛异常 → 回落原文（fail-open，不报错但白干）
④ 与现网同架构基底（mBERT-base 系列） 延迟档案与内存占用要能直接对比 延迟闸失去可比性

①②③ 是运行时硬条件；④ 是保住延迟闸的前提，不是运行条件。已知反例：XLM-R-large 的属性是 .roberta，③ 不满足 → 不是 drop-in（后手牌激活判据据此修订）。

4接入包：打包、传输、回滚素材

输出用途
SHA256SUMS逐文件哈希，shasum -a 256 -c 直用；落盘后第一件事
integration-pack.md由 docs/delivery/refine-integration.md 渲染（占位符 → 真实值，零手工）
verify-report.json打包那一刻的机读报告（无时间戳，内容寻址）

三条不可谈判性质

  1. verify 不过不许打包（门在打包之前）；
  2. 不覆盖已存在的输出目录（pack 是不可变产物）；
  3. 确定性 + 拒绝半渲染：认不出的占位符直接中止，不许有 {{…}} 漏进定稿。

目标机形态：私有 HF 仓 → 本地快照 sidecars/refine/models/<model-tag>/ + SHA256SUMS；运行时不再依赖 HF 可达性与凭据。旧快照原地不删——它就是回滚素材。

标签从哪来（打包前必看）：渲染时 MODEL_ID 取 config.json 的 _name_or_path，缺该字段就退回目录名，MODEL_TAG 再取它的 basename——暂存目录名会被直接写进宿主 patch 与指标标签。交付前把暂存目录命名为 beam-v1（或导出时写入 _name_or_path）。2026-10-14 实测：pilot 产物缺该字段，渲染出的标签是 checkpoint，注入路径会变成 models/checkpoint。

5切换与回滚 runbook

  1. 落盘快照 → 校验 sha256 → 跑 delivery verify。
  2. 打接入包 patch（改动被刻意限制在少数几处）。
  3. 冷启动 sidecar → GET /health 必须 {"status":"ok","compressor":true}（false = light mode，停）。
  4. stub 冒烟（零网络零花费，验接线）。
  5. 真链路回归：冻结考卷全量，149 条 ≈ 600 次网关调用，走宿主网关账本。
  6. 核判据 → 切换 → 观察（applied / fallback / skipped + 按压缩机标签的 token 节省）。
  7. 异常回滚：git revert + 重启。
判据（合取，别只读半句）

任务级质量 delta 的 95% CI 下界 ≥ 0 且 压缩率或 fact recall 有一项显著提升。
持平 = 不替换。负结果归档，refine 继续用公开 checkpoint。

回滚不残留脏缓存：缓存键含压缩机身份，换过权重后旧条目 key 不同，自然失效。（这原本是真实的坑——键里不含压缩模型时换完权重仍会静默命中。）

6再交付触发器与断供

触发器说明
真链路回归跌破验收线影响压缩面/权重的改动后必须跑真链路全量，结果摘录入本仓归档
负载分布漂移golden 主动扩集 + 线上聚合指标（节省率/fallback/延迟）漂移告警；均为代理信号，不声称测质量
训练语料许可变化许可链断了就不能再供
v2 立项换的不只是权重，还有接口——属另一次交付

无触发不交付。断供 ≠ 断服务：产物自包含（本地快照 + 旧模型并存，from_pretrained(本地路径) 离线可跑），Beam 停止不影响 refine 运行与回滚。

7命令速查

# 契约校验：两层七项，三种判定（PASS / VIOLATION / UNVERIFIED）
uv run beam delivery verify <checkpoint 目录>
uv run beam delivery verify <checkpoint 目录> --report verify.json
uv run beam delivery verify <checkpoint 目录> --static-only    # 跳加载层
uv sync --group load                                          # 打开加载层（torch + transformers）

# 打包：verify 不过则拒绝；输出目录必须不存在
uv run beam delivery pack <checkpoint 目录> --out <输出目录>

# 目标机落盘后
shasum -a 256 -c SHA256SUMS

退出码：delivery verify 0 = 通过（含加载层 UNVERIFIED 的情形），非 0 = 契约违反。判定细节要看报告，别只看退出码。
