压缩术语表

这套词汇表在每一课里保持一致。中文是工作语言，英文是代码与论文里的原名——两者一一对应。

维护：新增术语只在本页登记，课文里出现的词必须能在这里查到

A机制

抽取式压缩extractive compression
只删不增：输出是输入的token 级子序列。与之相对的是生成式压缩（改写、重排、缩写），代码与本项目都明确排除后者。 decisions.md §2 · compressor.py 注释
子序列保证subsequence guarantee
「输出一定是输入的子序列」这条安全性承诺。注意层级：它成立于 token 层面。字符串层面会漂移——WordPiece 解码会插入空格（#A-1029 → # A - 1029），SentencePiece 解码会把相邻片段粘连（driven + ly → drivenly）。 lesson 0001 §7 · assets/data/trace-en.js
保留概率keep probability, p(keep)
模型对每个 token 输出的、取第 1 类（keep）的 softmax 概率，值域 [0, 1]。它回答的不是「这个词多重要」，而是「教师模型在这个位置会不会删掉它」。 compressor.py:164
压缩档位aggressiveness
保留概率的绝对阈值，取值 0–1，运行时默认 0.2；请求头 x-tc-refine-aggressiveness 可覆盖。判据是 p >= 档位。 别说：压缩率 / 压缩强度 / 等级——它不是比例，见下一行 server.py:57 · compressor.py:194 · gateway refine.rs:41
保留率retention / kept ratio
留下的 token 数 ÷ 原 token 数。它是结果，不是设定值。
压缩率compression ratio
1 − 保留率，按两种口径同时报告：计费口径（tiktoken cl100k_base，代表客户账单）与模型原生口径（WordPiece / SentencePiece，代表模型视野）。两个口径的数字从不相等。 别说：节约率（那是计费侧的对偶说法，口径不同） docs/evaluation.md · native_tokens.py
强制保留force-keep
绕过概率、把 p(keep) 直接写成 1.0 的机制，共三处：特殊 token（[CLS]/[SEP]）、事实命中的 token、保护段覆盖的 token。 compressor.py:167–191
事实fact
被 _FACT_PATTERN（#[\w-]+|\d+(?:[.,:/-]\d+)*%?）命中的数字与编号：订单号、日期、版本、百分比、带小数点或千分位的数字。判定用 token 字符区间与事实区间的重叠。 refiner.py:78 · quality.py:33（逐字复制的同一正则）
保护段protected span
<tc_keep>…</tc_keep> 标记的内容，语义同事实。全部保护内容合计不得超过输入的 50%（防「整段包起来」关闭压缩）。 keep.py:28 · ADR-0079 §3
分块chunking
超过 BERT 的 512 token 窗口时的处理：按句边界打包成每块 ≤ 480 token 的块（超长单句退化到按词、最后按字符切），逐块压缩后用单空格拼接。阈值按块生效，块间互不可见。 compressor.py:28–30, 96–112, 231–276

B训练侧

数据蒸馏data distillation
把教师模型的压缩行为变成训练标签的五步管线：切块 → 教师压缩 → 滑窗模糊匹配 → 质控 → 微调。本项目的核心方法继承自 LLMLingua-2。 src/beam/distill.py · docs/data-strategy.md
教师teacher
执行抽取式压缩、产生标签来源的强模型（论文中为 GPT-4 级），经自有网关调用，成本进内部账本。
滑窗模糊匹配sliding-window fuzzy matching
把教师输出里的词按顺序对回原文位置，窗口默认 150 个词，每条匹配至多滑 window/2。它是启发式，产生的标签必然有对不齐的地方——这正是质控要丢样本的原因。 distill.py:250 match_labels
变差率Variation Rate, VR
教师输出里在原文中找不到对应位置的词所占比例（1 − find_rate），作为幻觉的代理信号。丢弃波动最大的 5%。 distill.py:298 · docs/data-strategy.md
对齐间隙Alignment Gap, AG
hitting_rate − matching_rate：教师确实保留了、但匹配器没能标注回来的部分。0 表示完美对齐。丢掉最差的 10%。 distill.py:298 quality_control

C评测侧

事实召回率fact recall
原文里的数字事实在压缩后文本中逐字存活的比例（字符串包含判定）。现网 mBERT 五档均为 0.7699；第一课的诊断认为这个缺口主要来自解码空格而非模型删除。 quality.py:43 · lesson 0001 §7
token F0.5
token 级对齐的 F 值，β²=0.25（精确率权重是召回率的两倍）——删掉填充词是压缩的目的，召回率下降是设计；凭空多出来的 token 才是罪。harness 用恒等对齐算下界，运行时 guardrail 用 embedding 余弦。 quality.py:55 · refiner.py 相似度 guardrail
质量 delta
同一批 prompt，压缩后与原文各跑一次下游任务，LLM judge 按 key_points 打分后的差值；用种子化配对 bootstrap 给出 95% 置信区间，下界不为负才叫没掉分。 docs/evaluation.md
验收尺yardstick
任务级评测基线在本项目中的角色——「微调后优于公开 checkpoint」的唯一度量。没有尺，不许声称赢。 别说：门槛 / gate（立项已 go，它不是决策闸门） CONTEXT.md
fail-open
宿主对 refine 的故障语义：压缩或改写任何一环出问题，就原样放行原文，绝不阻断请求。这意味着压缩模型的所有收益都是「最好情况」，所有故障都必须是无害的。

D交付与接入

产物包artifact pack
v1 的交付单元，五件缺一不算交付：checkpoint + 溯源 model card + 对照报告 + 延迟档案 + 接入包。 别说：模型文件、权重包（那是五件里的第一件） CONTEXT.md · docs/roadmap.md 阶段 5
接入包integration pack
产物包第五件——让宿主照做即可接入的单元：drop-in 契约校验清单 + 宿主改动 patch + 切换·观察·回滚 runbook + 非差异清单。它包含可执行契约，不只是说明。 别说：集成文档、集成指南 CONTEXT.md · docs/delivery/refine-integration.md
drop-in 契约drop-in contract
一个 checkpoint 能否替换压缩阶段的四条硬性条件：① architectures 含 BertForTokenClassification、num_labels=2、id2label = {0: drop, 1: keep}（宿主按位置读第 1 列当保留概率）；② tokenizer 必须是 fast（force-keep 靠 offsets 定位事实）；③ 模型类暴露 .bert（refiner.py:338 直调）；④ 与现网同架构基底。任何一条不满足，宿主就得改代码——那就不再是「替换权重」。 别说：兼容性要求（它指的是这四条可执行的检查） docs/decisions.md §6 · src/beam/delivery.py
静态层 / 加载层
delivery verify 的两层。静态层（5 项）只读 config.json 与 tokenizer.json，默认依赖即可跑；加载层（2 项）真实 from_pretrained 实例化，断言 .bert 与运行时 offsets，需要重依赖（uv sync --group load）。 delivery.py run_static_checks / run_load_checks
三种判定pass / violation / unverified
每层给出三种结果之一。UNVERIFIED 永远不算 PASS——它只说明这次没证明（依赖不在场或显式跳层）。交付记录必须能指出哪一次是双层 PASS。 别说：失败（unverified 不是失败，但也不是通过） delivery.py 模块 docstring
本地快照local snapshot
权重交付到目标机后的落盘形态：sidecars/refine/models/<model-tag>/ 加一份 SHA256SUMS。运行时不再依赖 HF 可达性与凭据；旧快照原地不删，它就是回滚素材。 docs/delivery/refine-integration.md §2
非差异清单non-diff list
接入包里明确列出「切换后不变的东西」——协议、请求头、rewrite 阶段、fail-open、guardrail、缓存与超时行为。作用是省掉收件人自己推演影响面。 docs/delivery/refine-integration.md §5
延迟闸latency gate
交付的硬条件之一：compress 阶段 p95 ≤ 现网 checkpoint 的 1.2×。同架构基底（契约第 ④ 条）天然满足；这道闸主要防「换个更大的底座」那类场景。 docs/roadmap.md 阶段 5
供货supply
Beam → refine 的关系定位：交付自包含产物（权重快照），不是代码依赖也不是服务。再交付由触发器驱动，无触发不交付。 别说：上游依赖、集成 CONTEXT.md
再交付触发器re-delivery trigger
四条：① 真链路回归跌破验收线；② 负载分布漂移（代理信号，不声称测质量）；③ 训练语料许可变化；④ v2 立项。无触发则不交付。 docs/delivery/refine-integration.md §6
断供supply cutoff
Beam 项目停止供应的情形。因为产物自包含（本地快照 + 旧模型并存、可离线加载），断供不影响 refine 的运行与回滚——这是「交付物供货」优于「代码依赖」的地方。 docs/delivery/refine-integration.md §7
替换replacement（接入语境）
只换 compress 阶段的 checkpoint 权重，不含 rewrite 阶段与任何宿主改造之外的语义。判据为合取：质量 delta 的 95% CI 下界 ≥ 0 且压缩率或 fact recall 有一项显著提升；持平 = 不替换。 别说：接管、取代 refine CONTEXT.md · docs/decisions.md §6
