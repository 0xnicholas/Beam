压缩管线速查

一次 compress() 的全部决策规则、旋钮与已知破口。贴在墙上用的那一页。

代码坐标以 tokencamp-pro/sidecars/refine/ 为根 · 术语见术语表

1决策规则

p(keep) = softmax(BertForTokenClassification(text).logits)[:, :, 1]

p(keep) = 1.0       若 token 属于 [CLS]/[SEP]
                    或 token 字符区间与事实/保护段区间重叠

保留 ⇔ p(keep) >= 档位             # 档位 = aggressiveness，默认 0.2
输出  = decode(保留的 token ids)     # token 级子序列

三处强制 1.0 使它们对任意阈值免疫；min_tokens 保底（不足时按概率取 top-k）、max_tokens 硬上限（会真的截断，甚至截掉受保护的 token）。

4已知破口与限制

  • 解码空格（WordPiece）。事实每个 token 都保住了，字符串却可能被拆开（#A-1029 → # A - 1029）。逐字比对的事实召回会把它记成丢失。第一课的诊断：这正是 mBERT 0.7699 缺口的主要来源。
  • 解码粘连（SentencePiece）。相邻的保留片段会被粘成一个新词（driven + ly → drivenly）。子序列保证在 token 层，不在字符串层。
  • 块间不可见。>512 token 时，每块各自决策，跨块指代关系在压缩阶段即断裂。
  • 结构塌缩。分块结果用单空格拼接，原始换行与消息边界丢失。
  • 硬截断。max_tokens 无差别截断尾部，可能砍掉被强制保留的事实。
  • 阈值不连续。概率分布有空洞，抬档位可能一个 token 都不动（实测 0.3→0.4 保留数不变）。
